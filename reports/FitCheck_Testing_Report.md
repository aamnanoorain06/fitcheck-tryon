## Completed implementation follow-up

- The generation endpoint now maps Supabase `PGRST116` no-row results to HTTP 404 rather than 500 (`server.mjs`).
- API error responses retain their HTTP status in the browser client; a definitive generation 404 clears the stored active generation and stops polling (`src/App.jsx`).
- Entering History clears stale form validation errors (`src/App.jsx`).
- Existing upload flow uses signed Supabase uploads; actual tiny-object upload and cleanup were previously verified.
- The Vercel prototype adds a separate `build:vercel` mode into `public/_fitcheck`, a root-only rewrite, an Express framework preset, and private/no-store API headers. It leaves the ordinary local `dev` and `build` paths unchanged.
- The prototype's static output and local rendering pass; actual Vercel Function detection/routing remains blocked pending a preview.
- RunPod request/response handling has mocked unit coverage, including classification of a synthetic numeric-input mismatch. This does not establish that the private endpoint returned that error or that the current payload matches its worker schema. Real generation is deliberately not claimed or tested.
- Express handler tests use the existing exported `app` on an ephemeral local port, and cleanly close the listener. `server.mjs` already skipped automatic startup for `VERCEL=1` or `FITCHECK_SKIP_LISTEN=1`; that behavior was preserved. Validation-only requests were checked with external `fetch` guarded and made no external calls.
